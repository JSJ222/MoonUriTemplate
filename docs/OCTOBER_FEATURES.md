# 十月新增能力与边界

`TemplateCatalog::measure_requests` 对混合端点请求批量预检，返回精确 URI 输出字符长度，不构造最终字符串数组。它沿用逐请求输出上限、请求数上限和总输出上限，并在失败时保留请求下标。适合一次生成大量超媒体链接之前的容量核算。该操作仍需扫描变量和执行编码长度计算，并不是零成本；复杂度与输入和潜在输出长度同阶。

`TemplateCatalog::templates_using(variable)` 在编译目录中按原始目录顺序返回引用指定变量的端点名，每个端点最多出现一次。SDK 迁移时可从被删除或改名的字段反查影响范围，再使用既有 `Template::diff_contract` 做单模板静态比较。扫描代价与目录中变量引用数同阶，不判断这些端点在某次请求中是否实际展开该变量。

测试对照批量实际展开长度，覆盖空批次、总预算差 1、未知端点的请求下标、重复变量引用和无命中反查。十月章程的公开默认分支、远端 CI 与 mooncakes.io 发布需要在本地工作完成后独立核验；申报书须由申请人亲自定稿，原则上每人一个项目的限制也须确认。

## 十月第二轮：目录迁移与请求审查

`TemplateCatalog::diff_catalog(next)` 列出新增、删除和变更端点，连字面量路径变化也保留；每项变更附原有变量/运算符契约报告。`inspect_requests` 检查混合请求的全部诊断，限制请求、绑定及结果数量，返回请求索引和变量名，不包含绑定值。缺失变量属于提示，普通 RFC 展开允许省略。

`expand_requests` 现在先调用精确计量，再构造输出，确保总预算超限在生成 URI 数组前被拒绝。计量仍有输入编码的临时分配，展开需额外遍历一次。运行 `moon run examples/maintenance --target wasm-gc`。详见 [本轮审查与复杂度](SECOND_REVIEW.md) 和 [十月申报资料稿](../十月项目申报书.md)。
